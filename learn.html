Before take-off

Set up your flight deck

You need two windows: the game and the code. The game is what you test. The code is what you change.

  1. Play the game once. Try to collect all 10 coins.
  2. Use my-game.html for your edits. Keep index.html safe as the original answer key.
  3. Open my-game.html in a code editor. Notepad works; Notepad++ or VS Code is even better. Never use Word — it adds curly quotes that break code.
  4. After every change: save (Ctrl + S), then refresh the browser (Ctrl + R).

🔧 If something goes wrong

Press Ctrl + Z to undo your last change. If the page is blank, a quote or comma is probably missing. Compare your file with index.html — the working answer key is always there.

🏗️ How the game was built

The game was made in layers: first the HTML stage, then the CSS paint, then the JavaScript rules. If you ever want to build a game from a blank page, use the same order. For now, remixing a working game is a real and valuable coding skill — it is how professional programmers join a new project.

02

Mission two

Tune the mission

Real coder skill: changing variables and testing game balance.

⏱️ 15 min
Variables Numbers Testing

A variable is a labelled box that holds a value. The game has two important boxes: how long a round lasts, and how many coins you need to win.

  1. Search for SECTION 2 — GAME SETTINGS.
  2. Find these two lines:
    JavaScript · settings
    const GAME_SECONDS = 30;
const BAGS_TO_WIN = 10;
  3. Predict first. What would happen if you changed GAME_SECONDS to 10 and BAGS_TO_WIN to 3? Say it out loud before you touch the code.
  4. Change the numbers to 20 and 6. Save and refresh. The start screen and HUD will show your new rules. Play a round.
  5. Now try a tiny game: GAME_SECONDS = 5 and BAGS_TO_WIN = 10. Can you win? Why or why not?
  6. Choose settings that feel fun, then keep them.

🧠 What just happened?

The game uses these values in several places: the timer, the start screen, the HUD, and the win check. By changing one variable, you changed the whole game. That is why programmers use variables instead of typing the same number into ten different places.

✅ Success check

The start screen shows your new goal and time, the countdown matches, and you can explain why a 5-second game with a 10-coin goal is difficult.

👩‍🏫 Co-pilot prompt

Ask: “If we wanted the game to be fair for a younger cousin, which number would you change first?” There is no single right answer — the reasoning is the learning.

03

Mission three

Add a golden money bag

Real coder skill: HTML attributes, data, and arithmetic.

⏱️ 25 min
HTML attributes Data attributes Math Game balance

The game already has golden-bag paint and a rule for bonus points. It is waiting for you to tell one bag: “You are golden, and you are worth three coins.”

First, be a code detective

Find the three money-bag buttons in the HTML. Search for Shoot a money bag.

HTML · the three bags
<button class="bag" type="button" data-points="1" aria-label="Shoot a money bag">💰</button>
<button class="bag" type="button" data-points="1" aria-label="Shoot a money bag">💰</button>
<button class="bag" type="button" data-points="1" aria-label="Shoot a money bag">💰</button>

The data-points="1" is a secret note attached to the button. JavaScript reads that note when the bag is clicked. The scoring code looks like this:

JavaScript · how points work
const points = Math.max(1, Number(bag.dataset.points) || 1);
score = Math.min(score + points, BAGS_TO_WIN);
updateHud();

Number turns the text "1" into the number 1. Math.min makes sure the score never goes past your goal. The score changes, and then the screen updates.

Now make it golden

  1. Change the third bag button to this:
    HTML · the golden bag
    <button class="bag golden" type="button" data-points="3" aria-label="Shoot the golden money bag">💰</button>
    You changed three things:
    • golden turns on the golden paint that is already in the CSS.
    • data-points="3" tells the game this bag is worth three coins.
    • The aria-label now describes the golden bag for someone using a screen reader.
  2. Save, refresh, and start a round.
  3. Tap the golden bag. The score should jump by 3, and a “3 COINS!” label should appear below it.
  4. Think like a game designer: one golden bag makes the game much easier. Try BAGS_TO_WIN = 15 or 20. Which makes a fun, fair round?
Works class="bag golden"
data-points="3"
Buggy clues class="bag gold" → no gold paint
data-points="three" → gives 1 coin

🧠 What just happened?

An HTML attribute gives extra information to an element. class controls style. data-points stores game data. aria-label helps people who cannot see the screen. The same element can carry style, data, and an accessibility label at once.

🔧 If your golden bag misbehaves

  • It gives 1 coin: check that it says data-points="3" and not "three".
  • It is not golden: check the class is exactly bag golden.
  • The whole page is blank: a quote mark or angle bracket is missing. Undo and compare with index.html.

✅ Success check

One bag is clearly golden, tapping it awards three coins, and the game still finishes correctly at the goal.

👩‍🏫 Co-pilot prompt

Ask: “Where did the number 3 come from?” The child should point to the data-points attribute and the line that reads bag.dataset.points. This is the bridge between HTML data and JavaScript logic.

Mission four

Remix and debug

Real coder skill: changing code safely and fixing problems.

⏱️ 25 min
Remixing Strings Debugging Design

Now make the game feel like yours. Choose at least two remixes. Remember: one change, save, refresh, test.

Remix menu

  1. Change the flying money. Search for shot.textContent in SECTION 8. Change "💵" to "🪙", "⭐", or your own emoji. Keep the quotes around it.
  2. Slow the money down. In the same function, find duration: 330 and change it to 650. Test it. Is 650 too slow? Pick a number you like.
  3. Give the crew a new cheer. In SECTION 2, find the CHEERS list. Add a line such as "Sky Squad forever!" with a comma after the line before it.
  4. Add a fourth money bag. Copy one whole normal bag button (not the golden one!) and paste it right after the others. Because the game looks for every .bag, the new one joins automatically. You may want to raise the goal.

💡 How does the fourth bag work?

The line document.querySelectorAll(".bag") collects every element with the class bag. The game loops over that list and attaches a click listener to each one. You did not need to add any JavaScript. Good code is built to handle new pieces.

Bug Hunt 🐛

A bug is not a disaster. It is a clue. Try one of these tiny mistakes on purpose, then find and fix it. Use a copy if you want to keep your golden bag safe.

Bug 1: The weak golden bag

Change data-points="3" to data-points="three". The bag still looks golden, but gives only one coin. Why?

Fix: use the number 3, not the word three.

Bug 2: The invisible paint

Change class="bag golden" to class="bag gold". The bag works but looks ordinary.

Fix: the CSS class is spelled golden.

Bug 3: The impossible mission

Set GAME_SECONDS = 1 and BAGS_TO_WIN = 10. Try to win. This is not a syntax error — it is a design bug.

Fix: change one number until the game feels fair.

🔎 The Bug Detective’s checklist

  • What is the smallest change I made?
  • Does the code have all its quotes, commas, and closing brackets?
  • Can I undo it with Ctrl + Z?
  • What does the original index.html look like on that line?
  • Did I save and refresh before deciding it is broken?

✅ Success check

You changed the game in at least two ways, you found and fixed one bug, and you can describe what happened using the words variable, attribute, or event.

👩‍🏫 Co-pilot prompt

Ask: “What is one thing you would change if we had another hour?” Then ask, “What would you need to learn to build it?” That turns excitement into a next-step plan.

Running the Code Club

The manual is designed for one child with one adult, but it works for a small group. Four sessions of 20–30 minutes is plenty. Stop while it is still fun.

Session Focus What success looks like
1 Read the game, meet the crew, edit the CREW data. Changes names/roles/colors and tests them in both the crew cards and cockpit.
2 Variables and game balance. Predicts and tests new timer/goal values; explains why the game changed.
3 Trace a click and build a golden bag. Adds golden and data-points, sees +3 coins, balances the goal.
4 Remix and debug. Completes two remixes, fixes one deliberate bug, describes the cause.

Prep checklist

  • Open my-game.html once to confirm it runs in your browser.
  • Install a simple editor if you can: Notepad++, VS Code, or Sublime Text. Set a large font.
  • Keep index.html untouched as the reference solution.
  • Print the manual and certificate if you prefer paper.
  • No internet, accounts, or personal data are needed.

Five teaching moves that work

  1. Predict, test, explain. “What do you think will happen?” is more powerful than “Click that.”
  2. One change at a time. This is the core debugging habit.
  3. Let the child drive. You can point and ask, but let their hands be on the keyboard.
  4. Praise the process. “You found the exact line” beats “You’re so clever.”
  5. Make it theirs. If they want a pizza instead of money, help them change the emoji. Playfulness keeps the learning alive.

Common problems and fixes

Problem Likely cause Fix
Page is blank after a change. Missing quote, comma, or bracket. Undo (Ctrl + Z) and compare with index.html.
Changes do not show. The file was not saved or the browser is showing the old copy. Save, then refresh. Confirm you are editing the file you opened.
Golden bag gives 1 coin. data-points is a word, not a number. Use data-points="3".
Score jumps from 9 to 10, not 12. The code caps the score at the goal so the HUD never shows “12 / 10”. This is intentional. The win check still fires; discuss why we cap the score.
Emoji shows as an empty box. The browser or device is missing that emoji. Choose a common emoji such as 💰, ⭐, or 💵.

Words we used

HTML — the page’s structure: buttons, text, sections.
CSS — the page’s style: colors, layout, animation.
JavaScript — the rules that make the page interactive.
Element — one piece of the page, like a button or card.
Attribute — extra information on an element, like class or data-points.
Variable — a named box that stores a value.
String — text inside quotes, like "Emmanuel".
Number — a value used for math, like 30.
Function — a named set of instructions. It runs when called.
Event — something that happens, like a click or a timer tick.
Condition — an “if” question, like “Did the score reach 10?”
List / array — an ordered collection, like all four crew members.
Object — a group of labelled values, like one crew member.
Debug — find, understand, and fix a problem.
